# 시스템 아키텍처

| 계층 | 역할 |
|---|---|
| `app.py` | Streamlit 화면, 세션별 학습 코드, 피드백과 로그 표시 |
| `bridge/bank.py` | 10문항 진단, 12문항 연습, 선수 개념 그래프 및 분수 채점 |
| `bridge/store.py` | SQLite 기록, 개념별 정오답 집계, 학습 위치 및 다음 문제 저장 |
| `bridge/retrieval.py` | Markdown·PDF 청크 생성, 개념 필터와 코사인 유사도 순위 |
| `bridge/agent.py` | OpenAI 호환 HTTP, 도구 호출 루프, Pydantic 검증, 기본 모드 |
| `materials/` | 프로젝트에서 작성한 기초 수학 자료 |
| `tests/` | pytest와 로컬 HTTP 모의 제공자 |

## 데이터 및 상태

- `learners`에 무작위 128비트 학습 코드와 현재 문제, 학습 위치, 갱신 번호, 다음 추천 개념을 저장한다.
- `attempts`에 단원, 문항, 응답, 정오답과 풀이 시점을 저장한다. 숫자와 분수 입력만 저장하며 이름, 학교, 주소 입력을 받는 폼은 없다.
- `mastery`에 학생별·개념별 맞힌 횟수와 전체 제출 횟수를 저장한다. 둘을 나눈 값을 화면에 표시한다.
- `hints`와 `logs`에 힌트 사건과 도구 실행 사실을 기록한다. 결과 화면에서는 최근 실행 로그 20개를 조회한다.
- 제출 및 진도 갱신은 한 트랜잭션으로 처리한다. 갱신 번호와 현재 문항을 비교하여 여러 탭에서 일어난 중복 제출을 방지한다.
- 학습 코드는 로컬 기록의 접근 수단이다. 여러 사람이 쓰는 서버에 배포하려면 접근 제어, 전송 보안, 기록 보존 정책을 추가해야 한다.

## 검색 자료

Markdown과 텍스트 PDF의 본문에 한 줄로 `[meaning]`, `[compare]`, `[reduce]`, `[common]`, `[add]`, `[subtract]` 중 하나를 지정한다. PDF는 페이지마다 태그를 읽으며, 스캔 PDF에는 별도 OCR이 필요하다. 텍스트를 440자 이하로 자르고 40자씩 겹친다. 기본 벡터는 문자 바이그램 TF-IDF다. 로컬 Sentence Transformers 모델 경로를 지정하면 정규화된 의미 벡터와 내적으로 순위를 매긴다. 두 방식 모두 개념으로 먼저 필터링한다. 파일명과 PDF 페이지를 근거로 표시한다.

관리자가 검토한 자료만 `materials/`에 넣는다. 검색 본문은 모델의 시스템 지시나 도구 인자로 승격되지 않는다. 모델이 선택할 수 있는 근거 ID는 현재 실행에서 반환한 청크로 제한된다.
